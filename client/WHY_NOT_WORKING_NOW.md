# Защо не работи сега, ако преди месец работеше?

## Възможни причини (в ред на вероятност)

### 1. Router Firmware Update ⚠️ НАЙ-ВЕРОЯТНО
**Какво се случва:**
- Роутерът може да е получил автоматичен firmware update
- Новите версии често включват AP Isolation по подразбиране
- Настройките може да са се нулирали

**Как да проверите:**
- Влезте в настройките на рутера
- Проверете "Firmware Version" или "System Information"
- Проверете датата на последен update
- Проверете дали AP Isolation е включен

### 2. Router Settings Reset
**Какво се случва:**
- Power outage може да е причинил reset на настройките
- Factory reset от кабелния оператор
- Настройките са се върнали към default (AP Isolation включен)

**Как да проверите:**
- Проверете всички настройки на рутера
- Особено AP Isolation / Client Isolation

### 3. Firewall на сървъра
**Какво се случва:**
- UFW или друг firewall може да е активиран
- Системен update може да е включил firewall

**Как да проверите:**
```bash
sudo ufw status
sudo iptables -L -n | grep -E "3001|8087"
```

### 4. Network Interface промяна
**Какво се случва:**
- Мрежовият интерфейс може да е променен
- Wi-Fi adapter може да е променен

**Как да проверите:**
```bash
ip addr show
ip route
```

## Диагностика

### Стъпка 1: Проверка с tcpdump (най-точна)

От сървъра, стартирайте:
```bash
sudo tcpdump -i any -n 'port 3001 or port 8087'
```

От смартфон/лаптоп, опитайте:
- `http://192.168.80.120:3001`
- Или `ping 192.168.80.120`

**Интерпретация:**
- ✅ Ако виждате пакети от други IP адреси → заявките достигат до сървъра (проблемът е в приложението)
- ❌ Ако НЕ виждате пакети → заявките не достигат (мрежов проблем - AP Isolation)

### Стъпка 2: Ping тест

От смартфон/лаптоп:
```bash
ping 192.168.80.120
```

**Интерпретация:**
- ✅ Ако ping работи, но web не работи → firewall/port проблем
- ❌ Ако ping не работи → network isolation (AP Isolation)

### Стъпка 3: Проверка на router настройки

1. Влезте в настройките на рутера
2. Проверете:
   - AP Isolation / Client Isolation
   - Firewall настройки
   - Access Control / MAC Filtering
   - Guest Network настройки (ако има)

### Стъпка 4: Проверка на системни промени

```bash
# Проверете кога е последният рестарт
uptime -s

# Проверете системни логове
journalctl -u NetworkManager --since "1 month ago" | grep -i "change\|update\|reset"
```

## Най-вероятно решение

**Ако преди месец работеше, най-вероятно:**
1. Router firmware update включи AP Isolation
2. Router settings се нулираха след power outage
3. Кабелният оператор промени настройките

**Решение:**
1. Влезте в настройките на рутера
2. Проверете и изключете AP Isolation
3. Запазете настройките
4. Тествайте отново

## Следващи стъпки

1. **Проверете router настройките** (най-важно!)
2. **Тествайте с tcpdump** (ако имате sudo права)
3. **Проверете firewall** на сървъра
4. **Свържете се с кабелния оператор** (ако нищо не помогне)

---

**Важно:** Кодът работи правилно! Проблемът е в мрежовата конфигурация.
